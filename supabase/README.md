# 会員版データベース設計

このフォルダーは、Supabaseへ接続する会員版のデータ設計と、適用済みの追加マイグレーションを管理します。現在の講座生共有版とは入口を分け、会員版だけがSupabase Authと会員データを利用します。

## 保存するもの

- `member_profiles`: 利用者の表示名、プラン、利用状態、有効期限
- `member_feature_overrides`: 個別に追加・停止した機能
- `saved_subjects`: 命式を再現するための入力元情報
- `chart_snapshots`: 計算バージョンと、その時点の計算結果
- `admin_audit_logs`: 管理者が行ったプラン変更や利用停止などの記録
- `member_consents`: 一般の無料会員が同意した利用規約・プライバシーポリシーの版と日時

パスワードはこれらのテーブルへ保存しません。Supabase Authだけが安全なハッシュとして管理します。

## 保存命式の考え方

命式は、入力元情報を正本として保存します。保存した人を選択すると、現在の共通計算エンジンで再計算します。同時に、`calculation_version`付きの結果を保存できるため、ルール変更前の鑑定内容も後から確認できます。

歴史上の人物に対応するため、生年月日は単一の日時型ではなく西暦年・月・日を分け、1年から9999年まで保存します。本名は必須にせず、`display_name`へ「Aさん」などの名称を保存できます。

## 保護方針

Row Level Securityをすべての会員テーブルで有効にします。会員は自分が所有する保存命式と計算結果だけを参照・変更できます。プラン、利用停止、管理者記録、同意履歴はブラウザから変更できません。

一般の無料会員登録では、Supabase Authのメール確認が完了するまでログインできません。登録時にフリープランを設定し、同意履歴には規約の版・同意日時・登録経路を保存します。生のIPアドレスは保存せず、不正登録対策に必要な場合もサーバー側で不可逆な識別値へ変換します。

管理操作で使うSupabaseのservice roleキーは、将来Renderの環境変数にだけ設定します。HTMLやブラウザ用JavaScriptには絶対に含めません。

## 運用確認

サーバー専用の設定読込と接続確認は `supabase-server.js` にあります。`SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` の両方が未設定でも、現在の講座生共有版はそのまま動作します。

設定後は `npm run check:member-db` で接続状態を確認できます。この確認処理でも秘密鍵そのものは画面やログへ表示しません。新しいマイグレーションは、テスト通過後にSupabase SQL Editorへ適用し、その後Renderへデプロイして実際の確認メールと初回ログインを確認します。
